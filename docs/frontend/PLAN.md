# План: детектор ИИ-кода для фронтенда (JavaScript / TypeScript: React, Angular, Vue)

Статус: **черновик, ждёт ответов пользователя на вопросы** (в конце файла).

## 1. Что получится в итоге

- **Та же веб-страница**, что для C#: ссылка на MR → выбор языка → «Проверить».
  - Варианты языка: «C# (.NET)» и «JavaScript / TypeScript (фронтенд)».
  - Токен, галочка и выбранный язык запоминаются.
- **Отчёт в прежнем виде:**
  - вероятность Claude в %, вердикт, надёжность, короткое объяснение;
  - главные признаки ИИ и человека с примерами `файл:строка`, оценка по файлам, вклад групп.
- **Новое в отчёте — строка «Стек»**, например:
  - «TypeScript 4.1 · React 17 · Redux Toolkit · SCSS · Jest + Testing Library»;
  - «C# · .NET 8 · ASP.NET Core · EF Core · xUnit».
  
  Стек определяется по `package.json`, `angular.json`, `tsconfig.json`, `*.csproj` и импортам в файлах MR.
- **Консоль:** `run.sh <ссылка> --lang frontend`. Флаг `--lang` есть и в `batch`, `eval`, `calibrate`.
- **Версия 2.0.0.** Детектор C# работает как раньше: проверю, что на корпусе C# результаты совпадают до цифры.
- **Пользователю ничего дополнительно ставить не нужно:** весь код на C#, Node.js не требуется.

## 2. Как организовать репозиторий (ветки)

**Отдельная ветка на каждый язык — не нужна.**
- Все детекторы используют одно и то же ядро: GitLab-клиент, модель MR, сигналы MR (артефакты, коммиты, процесс), скоринг, калибровку, отчёты, веб-страницу.
- В разных ветках ядро начнёт расходиться. Каждое исправление в GitLab-клиенте придётся переносить cherry-pick'ами.
- Главное: веб-страница с выбором языка должна содержать все детекторы в одной сборке.

**Рекомендация — один репозиторий, одна основная линия, языки как модули:**
- **Основная ветка** (сейчас `claude/inspiring-lamport-i2ixa7`, лучше переименовать в `main`) — всегда рабочая версия со всеми языками.
- **Ветки и теги версий:** `v1`/`v1.0.0` (только C#), `v2`/`v2.0.0` (C# + фронтенд) и так далее — точки отката.
- **Короткие рабочие ветки на задачу** (`claude/...`) вливаются в основную после тестов.

**Структура:**
```
src/
  AiDetect.Core/                  — общее: модель MR, источники (GitLab/git/JSON), дифф, сигналы MR,
                                    скоринг, калибровка, отчёты, интерфейс ILanguageAnalyzer
  AiDetect.Languages.CSharp/      — детектор C# (Roslyn): экстрактор, сигналы, слои, конвенции, стек
  AiDetect.Languages.Frontend/    — детектор JS/TS: свой лексер и мини-парсер, React/Angular/Vue, CSS
  AiDetect.Cli/                   — консоль и веб, реестр языков
tests/
  AiDetect.Tests/                 — общие тесты и тесты C# (как сейчас)
  AiDetect.Frontend.Tests/        — тесты фронтенд-детектора
model/
  weights.csharp.json  weights.frontend.json      — веса отдельно на язык
corpus/
  csharp/   manifest-human.tsv  manifest-ai.tsv  ai-src/
  frontend/ manifest-human.tsv  manifest-ai.tsv  manifest-wild.tsv  ai-src/
docs/
  CONTEXT.md (общий конспект), csharp/ (исследование, оценка), frontend/ (исследование, оценка, этот план)
```

**Новый язык в будущем:**
- новый проект `AiDetect.Languages.X` с реализацией `ILanguageAnalyzer`;
- строка регистрации в реестре;
- корпус `corpus/x/` и веса `model/weights.x.json`.

Ядро и веб-страница не меняются: пункт в выпадающем списке появится сам из реестра.

## 3. Разбор кода JS/TS: свой мини-парсер на C#

Рассмотренные варианты:

| Вариант | Минусы |
|---|---|
| Компилятор TypeScript через Node.js | Второй рантайм на каждом компьютере (Mac, Windows коллег), отдельный процесс, сложнее `run.sh`/`run.cmd` |
| tree-sitter | Нативные библиотеки под каждую платформу (Mac arm64/x64, Windows) — хрупко при запуске у коллег |
| Acornima / Esprima (C#) | Только JavaScript, без TypeScript и шаблонов Vue/Angular |
| **Свой лексер и структурный разбор на C#** | Больше работы, но полный контроль |

**Выбираю свой разбор.** Признакам почти не нужно полное AST, им нужны:
- токены (комментарии, строки, шаблонные строки, операторы `?.`, `??`, `===`);
- объявления и их границы (функции, стрелочные функции, классы, методы, интерфейсы, типы, импорты и экспорты);
- вложенность и сложность, JSX-элементы и атрибуты, декораторы Angular, блоки Vue.

Свой разбор:
- устойчив к обрывкам и синтаксическим ошибкам;
- работает одинаково на всех ОС;
- не тянет зависимостей.

Состав:
- **Лексер JS/TS/JSX/TSX.** Строки; шаблонные строки с вложенными `${}`; регулярные выражения против деления (по контексту); комментарии и JSDoc; JSX-текст и атрибуты; generics `<T>` против JSX в `.tsx`; декораторы.
- **Структурный слой:** парные скобки, области, объявления, длина и вложенность функций, цикломатическая сложность, распознавание компонентов и хуков React.
- **Vue SFC:** разделение на `<template>`, `<script>` (`lang="ts"`, `setup`), `<style>` (`scoped`, `lang="scss"`).
- **Шаблоны Angular (`.html`) и Vue:** сканер HTML-атрибутов (`*ngFor`, `trackBy`, `v-for`/`:key`, `aria-*`, `data-testid`, `type="button"`).
- **CSS/SCSS/LESS:** лёгкий токенизатор для признаков стилей.

**Проверка надёжности:** прогнать разбор по всем файлам ~20 клонированных репозиториев (десятки тысяч файлов):
- без исключений;
- скобки сбалансированы;
- количество функций правдоподобно.

## 4. Исследование фронтенда (отдельный документ `docs/frontend/RESEARCH.md`)

**Источники:**
- работы 2023–2026 о детекции LLM-кода (в том числе на JS/TS);
- наблюдения об «отпечатках» Claude и Claude Code в React, Angular и Vue;
- собственные измерения на корпусе.

**Гипотезы**, которые проверю (за ИИ, если не сказано иное):
- **TypeScript-типизация:**
  - явные возвращаемые типы, `interface XxxProps`, `unknown` в `catch`, `as const`, union-литералы, `readonly`, `Record<>`;
  - за человека: `any`, `!`-утверждения, `@ts-ignore`, приведения `as`.
- **Современный синтаксис:**
  - `?.`, `??`, `const` почти всегда, `===`, шаблонные строки, `async/await`;
  - за человека: `var`, `==`, склейка через `+`, цепочки `.then()`.
- **Обработка ошибок (сильная гипотеза):**
  - `error instanceof Error ? error.message : 'Unknown error'`;
  - `console.error('Failed to load X:', error)`;
  - `if (!response.ok) throw new Error(...)`;
  - тройка состояний загрузка / ошибка / пусто.
- **Корректность (аналог CancellationToken, устойчиво к маскировке):**
  - `AbortController` в `useEffect`, функции очистки, флаг `cancelled`;
  - Angular: `takeUntil(destroy$)` / `takeUntilDestroyed` / `DestroyRef`, `async`-pipe;
  - за человека: подписки без отписки.
- **React:**
  - плотность `useCallback`/`useMemo`, вынесенные кастомные хуки;
  - `type="button"` на каждой кнопке, `aria-*`/`role`, `data-testid`, обработчики `handleX`;
  - за человека: `key={index}`, инлайн-стили.
- **Angular:** `private readonly` в DI, `inject()`, `OnPush`, `trackBy`, типизированные формы, `providedIn: 'root'`.
- **Vue:** `<script setup lang="ts">`, типизированные `defineProps<>()`/`defineEmits<>()`, `withDefaults`, `computed`.
  - За человека: Options API со `this.$refs`, `v-if` вместе с `v-for` на одном элементе.
- **Комментарии и документация:**
  - JSDoc у всех экспортов, `@param`/`@returns`;
  - повествовательные комментарии (`// Handle form submission`, `{/* Header */}`), пересказ кода;
  - язык комментариев (как в C#).
- **Стили:**
  - CSS-переменные, `rem`, `:focus-visible`, `transition`, `prefers-reduced-motion`, брейкпоинт 768px, комментарии-заголовки;
  - за человека: `!important`, `z-index: 9999`, вендорные префиксы.
- **Ручные привычки (за человека):** `console.log`, `debugger`, TODO/FIXME, закомментированный код, `eslint-disable`, опечатки, транслит.
- **Тесты:**
  - тесты в том же MR, `it('should …')`, AAA, `it.each`, `beforeEach(clearAllMocks)`, `screen.getByRole`/`userEvent`;
  - за человека: snapshot-тесты.
- **Форма MR:** выделенные `types.ts`/`constants.ts`/`hooks/`/`index.ts`, сторис и тесты к каждому компоненту.
  - Процесс и артефакты — общие с C#.

**Риски ложных срабатываний** (продумать поправки, как StyleCop для C#):
- **Prettier и ESLint** выравнивают форматирование у всех. Если в проекте есть Prettier, признаки форматирования ослабляются. Правила ESLint (`explicit-function-return-type`, `no-explicit-any`, `eqeqeq`, `prefer-const`) ослабляют соответствующие признаки.
- **Генераторы Angular CLI** (`ng generate`) создают шаблонные `*.spec.ts` с одним «should create» и пустые стили. Это не признак ИИ: распознать и исключить.
- **Сгенерированное:** `*.d.ts`, клиенты OpenAPI/GraphQL codegen, lock-файлы, снапшоты, минифицированный код, `dist/`, i18n-JSON.
- **«Возраст кода»:** человеческий корпус — до 2021 года, и новых API (сигналы Angular, `<script setup>`, `satisfies`) в нём ещё нет. Такие признаки нельзя считать ИИ-шными в лоб. Их сравниваю с кодом проекта (базовая линия) и держу с малым весом.

## 5. Корпус и оценка (методика C#)

**Человеческий корпус:**
- 120–150 MR из ~20 публичных фронтенд-репозиториев до 2021 года, 150–2500 добавленных строк JS/TS;
- примерно поровну React, Angular и Vue, TypeScript и JavaScript;
- кандидаты:
  - **React:** excalidraw, PostHog, appsmith, mattermost-webapp, react-admin, jitsi-meet, redash, outline;
  - **Angular:** bitwarden (web/jslib), dspace-angular, thingsboard ui-ngx, ever-gauzy, alfresco-content-app, ngx-admin;
  - **Vue:** directus, chatwoot, koel, owncloud web, hoppscotch, nextcloud deck;
  - **русскоязычные команды:** JetBrains ring-ui, VKUI, Tinkoff taiga-ui.

**ИИ-корпус** — в тех же репозиториях на коммитах 2020 года:
- 15–20 MR в обычном режиме Claude Code;
- 8–10 MR с маскировкой: «пиши как в проекте», русские комментарии, без JSDoc, короткие коммиты.

**Новое по сравнению с C# — «дикая» выборка:**
- настоящие коммиты Claude Code из публичных репозиториев GitHub 2025–2026 годов с трейлером. Поиск по GitHub находит больше 200 тысяч коммитов «Generated with Claude Code» с TSX;
- оцениваются без артефактов (`--no-artifacts`): насколько детектор узнаёт реальный код Claude, написанный реальными людьми с агентом, только по коду и процессу;
- это честная проверка полноты, которой не было для C#.

**Метрики** — как раньше:
- ROC AUC на 5-кратной перекрёстной проверке, ложные «ИИ» на людях при порогах 50% и 65%, полнота отдельно по режимам (обычный, маскировка, дикая выборка), отдельно по React, Angular и Vue.

**Цели:** AUC ≥ 0.9; ложных «ИИ» ≤ 3–5%; ни одного человеческого MR ≥ 65%.

## 6. Этапы работы

1. **Исследование:** `docs/frontend/RESEARCH.md` — литература, гипотезы, риски.
2. **Рефакторинг под много языков:**
   - интерфейс `ILanguageAnalyzer` и реестр;
   - C# в отдельный проект; общие слой, тесты и классификатор файлов;
   - веса по языкам (`weights.json` остаётся читаемым для совместимости).
   
   **Проверка:** пересобрать корпус C# и убедиться, что вероятности по всем 140 MR совпадают с версией 1.0.0.
3. **Лексер и мини-парсер JS/TS/JSX/Vue/Angular/CSS** с модульными тестами и прогоном по десяткам тысяч реальных файлов.
4. **Фронтенд-детектор:**
   - экстрактор признаков, сигналы по группам;
   - классификатор файлов (сгенерированное, тесты, сторис, слои: компонент, хук, стор, сервис или API, роутинг, стили, типы, утилиты, i18n);
   - конвенции (ESLint, Prettier, tsconfig `strict`, commitlint, husky), определение стека.
5. **Источники данных:**
   - GitLab подгружает `.ts/.tsx/.js/.jsx/.vue/.html/.scss/.css` и соседние файлы для базовой линии;
   - также `package.json` (корневой и ближайший к изменённым файлам — для монорепозиториев), `tsconfig`, конфиги ESLint и Prettier, `angular.json`;
   - то же для локального git и JSON.
6. **Веб, консоль, отчёты:**
   - выбор языка после ссылки на MR, строка «Стек» в HTML, консольном и JSON-отчётах;
   - предупреждение, если в MR есть код другого языка.
7. **Корпус:** человеческие MR, ИИ-образцы (обычные и с маскировкой), дикая выборка; манифесты и скрипт пересборки, как для C#.
8. **Калибровка и оценка:**
   - `model/weights.frontend.json`, `docs/frontend/EVALUATION.md`;
   - итерации: выкинуть или ослабить неразличающие признаки, добавить найденные.
9. **Тесты:**
   - модульные (лексер, экстрактор, анализатор, конвенции, стек, смешанные MR);
   - GitLab-клиент на поддельном сервере с фронтенд-файлами;
   - Playwright-тест страницы с выбором языка;
   - регрессия C#.
10. **Финал:**
    - примеры отчётов (PNG/HTML/PDF) для фронтенда;
    - README (запуск, выбор языка), `CHANGELOG` 2.0.0;
    - `docs/CONTEXT.md`, коммит и пуш.

После каждого этапа — коммит и пуш, `CONTEXT.md` обновляется. Если упрусь в лимит, заранее запланированное сообщение продолжит работу после сброса. Состояние всегда сохранено в git.

## 7. Вопросы пользователю

1. **Какой фронтенд у вашей команды?**
   - Angular, React или Vue; TypeScript или JS; примерные версии.
   - Есть ли Prettier/ESLint.
   - На каком языке комментарии и тексты интерфейса — русском или английском.
   - Фронт в отдельном репозитории или вместе с C#-бэкендом.
   
   От этого зависит, на чём сделать упор в корпусе и признаках. Если не знаете — покрою все три фреймворка поровну.
2. **Смешанные MR (C# и фронт в одном MR).**
   - Предлагаю анализировать только файлы выбранного языка. Сигналы MR (коммиты, артефакты, процесс) — общие. В отчёте — предупреждение «в MR есть ещё N строк C#».
   - Добавить ли третий пункт «Авто (по файлам MR)»? Рекомендую добавить, явный выбор языка сохранить.
3. **Субагенты для ИИ-корпуса.**
   - Самый реалистичный ИИ-корпус получится, если запустить отдельных агентов Claude Code. Каждый получает задачу в настоящем репозитории, сам изучает код, пишет фичу и тесты и коммитит, как это делают ваши разработчики.
   - Так быстрее и честнее, чем писать образцы в одном контексте, но расходуется больше лимита.
   - Разрешаете?
4. **Лимит.** Остаётся ли прежнее ограничение «не больше 70% недельного лимита»?
5. **Ветки в конце.**
   - Сейчас я пушу только в ветку сессии `claude/ai-detector-frontend-vfpcyq`.
   - После готовности можно влить работу в основную линию `claude/inspiring-lamport-i2ixa7` и создать ветку `v2`, как `v1`?
   - Переименовать основную линию в `main` (переключить ветку по умолчанию в настройках GitHub) — по желанию.
