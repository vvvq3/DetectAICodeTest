# План прототипа (утверждён пользователем)

## Форма
- Консольное приложение на C# (.NET 10, `RollForward=Major`) с разбором кода через Roslyn: `./run.sh <ссылка на MR>`.
- Режим `--web`: локальная страница на `localhost` с полем для ссылки (тот же движок).
- `run.sh` сам ставит .NET SDK в `~/.dotnet`, если его нет (Mac arm64/x64, без sudo).
- Отчёт на русском: вероятность, вердикт, надёжность, вклад групп, главные ИИ-паттерны с примерами `файл:строка`, признаки человека.
- **Никакие внешние сервисы не используются** — только GitLab пользователя.

## Источники данных MR (`IMergeRequestSource`)
1. GitLab API v4 (`PRIVATE-TOKEN` из `GITLAB_TOKEN`): MR (title, description, author, branches, diff_refs), коммиты (+ stats), диффы (`/diffs` с фолбэком на `/changes`), raw-файлы до/после, наличие `CLAUDE.md`/`.claude/*`, `.gitignore`, соседние файлы каталогов (дерево на base) для базовой линии, `.editorconfig`/`Directory.Build.props`.
2. Локальный git: `--git <repo> --base <ref> --head <ref>` (для тестов на публичных репозиториях и офлайн-проверок).
3. Сохранённый JSON: `--save mr.json` / `--load mr.json`.

## Предобработка
- Исключить сгенерированное: `*.Designer.cs`, `*.g.cs`, `Migrations/`, `*ModelSnapshot.cs`, `<auto-generated>`, `obj/bin`.
- Roslyn-разбор полного нового файла; область анализа = добавленные строки (для новых файлов — все).
- Классификация файлов: тесты, слой (контроллер/сервис/репозиторий/DI/DTO/валидация/options/маппинг/миграции/документация...).

## Группы сигналов (независимые, у каждой ограничен вклад)
- **A. Прямые артефакты** Claude Code: Co-Authored-By Claude, «Generated with Claude Code», ссылка на сессию, CLAUDE.md/.claude в диффе или в репо, ветка `claude/...`, описание `## Summary`/`## Test plan`, эмодзи.
- **Б. Стилометрия (Roslyn)**: комментарии/XML-doc, именование, синтаксис, защитный код, async/токены, логирование, исключения, структура, форматирование, тесты.
- **В. Сдвиг относительно нормы проекта**: те же признаки на существующем коде (старые версии файлов + соседние файлы) — снижает вес «конвенциональных» признаков и даёт отдельный сигнал сдвига.
- **Г. Форма MR и процесс**: число слоёв, тесты вместе с кодом и их доля, новые .md, доля новых файлов, стиль коммитов, fixup-коммиты, скорость (строк/час между коммитами), описание MR, единообразие стиля по файлам.
- (Тест переписыванием через внешний API — **исключён по требованию**.)

## Модель
- Каждый признак → свидетельство e ∈ [-1, 1] (кусочно-линейно между «типично для человека» и «типично для ИИ») × надёжность r = n/(n+k) × вес w → вклад в логит. Сумма по группе ограничена; итог p = sigmoid(Σ / T).
- Веса — экспертные из исследования, затем подгонка на корпусе (логистическая регрессия с L2 к экспертным весам, знаки зафиксированы). Команда `calibrate` для дообучения на размеченных MR пользователя.
- Флаг `--no-artifacts` — проверить детекцию только по коду.

## Проверка (ночью)
- Модульные тесты признаков.
- Корпус: человеческий код из публичных C#-репозиториев (коммиты до 2021 года), ИИ-код — MR, написанные Claude по задачам в стиле Claude Code (обычный режим и «стиль проекта»).
- Метрики: ROC AUC, FPR на человеческом коде, полнота в режиме маскировки.
- Проверка GitLab-клиента на публичных MR gitlab.com.

## Вне прототипа
Помесячная агрегация по разработчику с поправкой Рогана–Гладена, нейросетевой классификатор, телеметрия.
