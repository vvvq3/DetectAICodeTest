# Требования заказчика (сохранено дословно по смыслу, приоритет №1)

## Исходная задача (первое сообщение)
- Сделать программу: на вход — ссылка на MR из GitLab, на выход — **процент уверенности, что код MR написан ИИ**.
- MR на **C# / .NET**; код написан **либо человеком, либо Claude Code** — других вариантов нет. Прототип — только C# + Claude.
- Учесть **все главные признаки ИИ-кода из PDF-исследования** (выжимка — `docs/RESEARCH.md`).
- На итоговом экране: не только вероятность, но и **краткая детализация — почему так решено, какие главные паттерны ИИ найдены в коде**.
- Весь код — в GitHub-репозитории пользователя `vvvq3/DetectAICodeTest` (ветка `claude/inspiring-lamport-i2ixa7`), регулярно коммитить и пушить.
- Способ получения кода MR не главное — считать, что есть полный доступ к GitLab, MR, диффам.
- Главное — **алгоритм детектирования по всем основным критериям из PDF**.
- В конце пользователь должен **запустить прототип на своём Mac** и проверить на нескольких MR своего C#-проекта.

## Ответы на уточняющие вопросы
1. GitLab — **собственный сервер** пользователя; доступы (токен) даст потом. → токен через `GITLAB_TOKEN`, хост берётся из ссылки, есть флаг `--insecure` для самоподписанных сертификатов.
2. .NET на Mac, скорее всего, не установлен → скрипт `run.sh` сам ставит .NET SDK локально (без sudo).
3. **Никуда во внешние сервисы код отправлять нельзя.** Каждый фактор должен покрываться **локальным кодом**. (Тест переписыванием через Claude API — НЕ делать.)
4. Как программисты используют Claude — неизвестно, каждый по-разному (возможна маскировка: без трейлеров, CLAUDE.md «пиши как в проекте» и т.п.).
5. **Не опираться на даты** (нет «чистой» даты до ИИ). Анализировать любой MR по коду и признакам.
6. (не ответил) стиль команды — определять автоматически по коду репозитория.
7. MR будут **средние или большие: минимум ~150 строк кода**, часто больше.

## Дополнительные указания (второе сообщение)
- Работать автономно всю ночь, к утру — рабочий прототип.
- При упоре в дневной лимит — восстановить работу сразу после сброса (запланировано напоминание). Не тратить больше ~70% недельного лимита.
- При переполнении контекста — самому оптимизировать, но **сохранить все запросы пользователя, PDF-исследование и план** (этот файл, `docs/RESEARCH.md`, `docs/PLAN.md`, `docs/PROGRESS.md`).
- Если основное готово за 1–2 часа — продолжать улучшать: **больше тестов**, взять **публичные C#-репозитории** и прогнать на них, **добавить больше критериев** (даже менее значимых), можно проводить доп. исследования и брать **открытые библиотеки** для подзадач.
- Цель утра: рабочий прототип, определяющий, кто написал C#-код — Claude или человек.
